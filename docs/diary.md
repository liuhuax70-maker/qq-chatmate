# 日记 — 设计说明

> 需求原文：「在我发消息吐露心声时，能给我记录，当做第二人称的日记（以大肥鱼的视角），
> 来记录我的生活。以每天的日期为准，每天新建一个文件，每次聊天把有价值的、
> 跟我有很大关联的事件追加到日记文件中，日记文件夹位置在：D:\日记」

---

## 一、它长什么样

位置：`D:\日记\2026-10-26.md`

```markdown
# 2026 年 10 月 26 日

## 14:30

你说面试挂了，还加一句自己特别没用。我尾巴差点拍你脸上——谁准你这么说的。
挂了就挂了，你平时那股劲儿呢。我懒得哄你，但你要是真信了自己没用，我第一个不答应。

## 18:05

你妈又催你找对象了，你嘴上说烦死了，我就嗯了一声没接话。其实我想问你是不是真不想找，
又觉得这话轮不到我一条鱼来问。
```

**格式**：`# 日期` → `## 时间` → 正文（第二人称）

同一天多聊几次就多几个时间段，追加在同一文件里。

---

## 二、写什么 / 不写什么

这是整个功能最关键的设计：**不是每句话都记**。

如果每句都记，日记会变成聊天记录，回头看毫无价值。

### 判断流程

```
收到消息
  ↓
① 长度预筛（< 6 字直接跳过，省一次 LLM 调用）
  ↓
② 噪音黑名单（在吗 / 嗯 / 哈哈 / 6 / ？... 直接跳过）
  ↓
③ LLM 判断「值不值得记」  ← 核心
  ↓ true
④ LLM 生成日记正文
  ↓
⑤ 追加到 D:\日记\YYYY-MM-DD.md
```

### 值得记（三个条件全满足）

1. 阿龙在说**他自己的事** —— 经历、感受、想法、困扰、计划、回忆
2. **有实质内容** —— 不是寒暄、不是问句、不是指令、不是单纯吐槽一句
3. **有分量** —— 以后回头看有意义，能看出他当时的状态

### 实测结果

| 消息 | 判定 |
|---|---|
| 今天面试挂了，感觉自己特别没用 | ✅ 记 |
| 我妈又催我找对象了，烦死了 | ✅ 记 |
| 其实我一直觉得自己不适合做这行 | ✅ 记 |
| 刚才路过以前上班那栋楼，突然挺难受的 | ✅ 记 |
| 我最近老是睡不着，一躺下就胡思乱想 | ✅ 记 |
| 在吗 | ❌ 跳过 |
| 你几岁了 | ❌ 跳过（问的是她的事） |
| 唱首歌 | ❌ 跳过（指令） |
| 今天天气不错 | ❌ 跳过（太泛） |
| 哈哈哈哈 | ❌ 跳过 |
| 帮我查一下明天几号 | ❌ 跳过 |

**6/6 判定正确。**

## 三、为什么是第二人称

需求明确说了「第二人称」—— 阿龙是「你」。

这个视角的差别：

| 视角 | 效果 |
|---|---|
| ❌ 第三人称 | 「今天阿龙说面试挂了」—— 像旁观者在写别人的事 |
| ❌ 第一人称 | 「我今天听他说面试挂了」—— 太自我，焦点跑了 |
| ✅ 第二人称 | 「你说面试挂了，还加一句自己特别没用」—— **像在跟他说话**，日记是他俩之间的东西 |

prompt 里还额外要求：
- 语气是她的：嘴上不耐烦，心里在意
- 只写这一件事，不扯别的
- 2-5 句，不超过 180 字
- 不要「今天阿龙说」这种转述腔
- 不要总结、不要说教、不要给建议
- 不用 markdown 加粗、不要小标题

## 四、一天一个文件

| 情况 | 行为 |
|---|---|
| 当天第一次写 | 新建 `YYYY-MM-DD.md`，写 `# 日期` 头 |
| 当天再写（不同分钟） | 追加 `## HH:MM` + 正文 |
| 当天再写（同一分钟） | **不重复起时间戳**，直接接在上一段下面 |
| 跨零点 | 自动切换到新日期的文件 |

最后一条是实测发现的问题：一次测试里 5 条日记连续写入，全是 `## 04:44`，
看起来像坏了。现在同一分钟只起一个时间段。

## 五、怎么改位置（exe 里）

**主窗口 → 人格设定 → 「日记（可修改）」标签页**

| 控件 | 作用 |
|---|---|
| 启用日记 | 复选框 |
| 日记目录 | 输入框 + 「浏览…」按钮（系统文件夹选择器） |
| 状态预览 | 显示今天的文件路径、是否已写、历史多少天 |
| 打开日记文件夹 | 资源管理器直接打开（不存在会自动创建） |
| 看今天写了什么 | 弹窗显示今天的日记全文 |

保存后写到 `qq-netizen\config\local.yaml`：

```yaml
diary:
  enabled: true
  dir: "D:\\我的 日记\\2026"
```

**为什么不改 default.yaml**：
- `local.yaml` 优先级高于 `default.yaml`（配置加载逻辑本来就是这样）
- `local.yaml` 在 `.gitignore` 里，不会把本机路径提交到仓库

⚠️ 路径里的反斜杠在 YAML 双引号里要写成 `\\`，启动器写入时自动转义、读取时自动还原。

## 六、人格参数化（第 3 项需求）

需求：「exe 文件中可以设置有参数的部分人格，其它人格特性仅供展示。」

人格设定窗口现在分三个标签页：

### 标签页 1：人格参数（可修改）

| 字段 | 注入位置 | 说明 |
|---|---|---|
| 名字 | `<role>` | |
| 自称 | `<role>` | |
| 年龄 | （不注入 prompt，仅展示） | |
| 口头禅 | `<voice>` | 中文逗号分隔 |
| 人设事实 | `<about-self>` | 一行一条 |
| 背景设定 | `<role>` | 整段文本 |

### 标签页 2：日记（可修改）

见上一节。

### 标签页 3：固定人格（只读）

只读显示 `system.md` 的 9 个段落标题 + 每段前 6 行摘要，
以及 `rules.md` 的全部红线。

**要精修**：点「性格设定原文」按钮，用记事本直接编辑 `system.md`。

### 为什么这么分

| | 可编辑 | 只读 |
|---|---|---|
| 内容性质 | 数据（名字、列表、路径） | 行为描述（大段自然语言） |
| 表单能否表达 | 能 | 不能 |
| 改坏了会怎样 | 一眼看出来 | 人格崩坏，很难定位 |
| 例子 | 名字 = 大肥鱼 | 「七分软三分硬」「别用破折号做插入语」 |

把 `<character>` 那 50 行做成输入框，用户既不知道怎么改，改坏了也看不出来。

## 七、技术实现

### 文件

| 文件 | 作用 |
|---|---|
| `src/diary/index.ts` | 日记核心：判定 → 生成 → 追加 |
| `src/config/index.ts` | `diary` 配置段（zod schema） |
| `src/index.ts` | 接入 `handleReply`，`void` 异步调用 |
| `src/server/http.ts` | `/api/diary/today`、`/api/diary/list` |
| `tests/diary.ts` | 40 项断言 |

### 关键设计

**1. 绝不阻塞对话**

```ts
if (cfg.diary.enabled) {
  void diary.maybeWrite(text, session.shortTerm.slice(-10)...);
}
```

用 `void` 而不是 `await`——写日记慢一点、失败都无所谓，回复必须准时。

**2. 绝不抛异常**

`maybeWrite` 整个包在 try/catch 里。LLM 挂了、磁盘满了、权限不足，
都只记一条 warn 日志，对话照常。

**3. 并发保护**

```ts
if (this.writing) {
  this.logger.debug('上一条日记还在写，跳过这次');
  return null;
}
```

避免两条消息同时触发写文件，把内容写串。

**4. 可注入时钟**

```ts
now: () => Date = () => new Date();
```

测试里替换成固定时间，才能验证「同一分钟合并 / 跨分钟分开 / 跨天换文件」。

## 九、已知限制

1. **每条要两次 LLM 调用**（判定 + 生成）。
   预筛能挡掉大部分噪音，但真正聊起心事时每条多花约 1-2 秒后台时间、约 500 token。
   可以关掉 `enabled` 或调高 `minChars`。

2. **判定不是 100% 准**。
   偶尔会漏记（该记的没记）或多记（不该记的记了）。
   这是 LLM 判定的固有不确定性，prompt 调得再细也有边界。

3. **日记不可编辑**（从 exe 里）。
   可以直接用记事本改 `.md` 文件。

4. **同一分钟的多条日记没有分隔标题**。
   只在中间空一行。这是刻意的——一排相同的 `## 04:44` 更难看。
