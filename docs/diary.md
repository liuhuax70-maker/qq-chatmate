# 日记 — 设计说明

> 需求原文（第一版）：「在我发消息吐露心声时，能给我记录，当做第二人称的日记（以大肥鱼的视角），
> 来记录我的生活。以每天的日期为准，每天新建一个文件，每次聊天把有价值的、
> 跟我有很大关联的事件追加到日记文件中，日记文件夹位置在：D:\日记」
>
> 需求原文（格式重构，2026-10-26）：「日记格式大概是下面这样，但是是以大肥鱼的视角来记录我的日常」
> ——附了一份完整样例（日期/星期/天气 → 地点 → 心情 → 标题 → 开头/正文一二三/结尾）

---

## 一、格式

位置：`D:\日记\2026-10-26.md`

```markdown
2026年10月26日  星期一  晴
地点：家中
心情：有点想笑，又有点馋

标题：油锅惊魂记

【开头】
阿龙，你今天头一回自己开火做饭，我在旁边看着，心里比你还紧张——毕竟油一溅，
你那个反应，我差点以为你要跳起来。

【正文一：发生了什么】
你说今天第一次自己做饭，做的是西红柿炒鸡蛋。切西红柿、打蛋、下锅，油一热就溅出来，
吓你一跳。最后你妈尝了，说还不错。

【正文二：细节】
我注意到你说「吓我一跳」的时候语气还有点后怕，但提到你妈说「还不错」时，
尾巴明显翘起来了。油溅那一下，你大概往后缩了半步吧。

【正文三：感受和想法】
我嘴上想说「炒个鸡蛋至于吗」，但心里明白，头一回站灶台前谁不慌。
你妈那句「还不错」，估计比什么夸奖都管用。

【结尾】
今天你算是把火点着了，明天要不要再试一道？我就在旁边趴着，油溅到你我可不管。
```

### 字段对照

| 样例里的 | 实现 | 来源 |
|---|---|---|
| `2026年10月26日` | 当天日期 | 系统时间 |
| `星期一` | 星期几 | 系统时间 |
| `晴` | 真实天气 | wttr.in API |
| `地点：家中` | LLM 判断 | 从对话推测 |
| `心情：……` | LLM 生成 | 她的心情 |
| `标题：……` | LLM 生成 | 4-10 字 |
| `【开头】` | LLM 生成 | 一句总述 |
| `【正文一：发生了什么】` | LLM 生成 | 事件经过 |
| `【正文二：细节】` | LLM 生成 | 具体画面 |
| `【正文三：感受和想法】` | LLM 生成 | 她的看法 |
| `【结尾】` | LLM 生成 | 收尾 + 明天 |

## 二、两个核心约束

### 1. 第二人称 + 大肥鱼视角

这是需求里最强调的一点。

| 视角 | 效果 |
|---|---|
| ❌ 第三人称 | 「今天阿龙第一次自己做饭」—— 像旁观者在写别人的事 |
| ❌ 第一人称 | 「我今天听他说做饭」—— 太自我，焦点跑了 |
| ✅ **第二人称** | 「你今天头一回自己开火做饭，我在旁边看着」—— **像在跟他说话** |

prompt 里的原文：

```
⚠️ 最重要的两条：
1. **用第二人称「你」称呼阿龙** —— 你在写他，但像在跟他说话
2. **视角是你自己（大肥鱼）** —— 你看到的、听到的、想到的，不是全知视角
```

### 2. 天气必须真实

样例第一行有「晴」。如果每天都是「晴」会露馅。

- 数据源：`wttr.in`（免费、无需 key、支持中文城市名）
- 英文天气词自己做映射：`Sunny` → 晴、`Patchy rain nearby` → 小雨、`Overcast` → 阴……
- 一天只请求一次（缓存）
- **拿不到就空着**——第一行变成「2026年10月26日  星期一」，绝不硬编

实测：`北京 → 晴`、`成都 → 小雨`（Patchy rain nearby）、`哈尔滨 → 晴`

## 三、写什么 / 不写什么

**不是每句话都记**。每句都记的话，日记会变成聊天记录。

### 判断流程

```
收到消息
  ↓
① 长度预筛（< 6 字直接跳过，省一次 LLM 调用）
  ↓
② 噪音黑名单（在吗 / 嗯 / 哈哈 / 6 / ？... 直接跳过）
  ↓
③ LLM 判断「值不值得记」  ← 核心
  ↓ true
④ LLM 生成结构化 JSON（8 个字段）
  ↓
⑤ 渲染成日记格式 → 追加到文件
```

### 值得记（三个条件全满足）

1. 阿龙在说**他自己的事** —— 经历、感受、想法、困扰、计划、回忆
2. **有实质内容** —— 不是寒暄、不是问句、不是指令、不是单纯吐槽一句
3. **有分量** —— 以后回头看有意义，能看出他当时的状态

### 实测结果

| 消息 | 判定 |
|---|---|
| 今天第一次自己做饭，西红柿炒鸡蛋，油溅出来吓我一跳 | ✅ 记 |
| 今天面试挂了，感觉自己特别没用 | ✅ 记 |
| 我妈又催我找对象了，烦死了 | ✅ 记 |
| 其实我一直觉得自己不适合做这行 | ✅ 记 |
| 在吗 | ❌ 跳过 |
| 你几岁了 | ❌ 跳过（问的是她的事） |
| 唱首歌 | ❌ 跳过（指令） |
| 今天天气不错 | ❌ 跳过（太泛） |
| 哈哈哈哈 | ❌ 跳过 |

## 四、一天一个文件

| 情况 | 行为 |
|---|---|
| 当天第一次写 | 新建 `YYYY-MM-DD.md`，直接写完整结构 |
| 当天再写 | 追加 `────` 分隔线 + `HH:MM` + 新的完整结构 |
| 跨零点 | 自动切换到新日期的文件 |

同一天的多次记录是**独立的多篇**，不是合并成一篇——
因为需求说的是「每次聊天把有价值的追加到日记文件」。

**为什么不用 markdown 的 `---` 分隔**：会和正文里的破折号混淆，改用 `────`。

## 五、怎么改设置（exe 里）

**主窗口 → 人格设定 → 「日记（可修改）」标签页**

| 控件 | 作用 |
|---|---|
| 启用日记 | 复选框 |
| 日记目录 | 输入框 + 「浏览…」按钮（系统文件夹选择器） |
| 天气城市 | 输入框，留空 = 按 IP 定位 |
| 状态预览 | 今天的文件路径 / 是否已写 / 历史多少天 |
| 打开日记文件夹 | 资源管理器（不存在会自动创建） |
| 看今天写了什么 | 弹窗显示今天的日记全文 |

保存后写到 `qq-netizen\config\local.yaml`：

```yaml
diary:
  enabled: true
  dir: "D:\\日记"
  weather:
    city: "北京"
```

**为什么不改 default.yaml**：
- `local.yaml` 优先级高于 `default.yaml`（配置加载逻辑本来就是这样）
- `local.yaml` 在 `.gitignore` 里，不会把本机路径提交到仓库

⚠️ 路径里的反斜杠在 YAML 双引号里要写成 `\\`，启动器写入时自动转义、读取时自动还原。

## 六、人格参数化（配套需求）

需求：「exe 文件中可以设置有参数的部分人格，其它人格特性仅供展示。」

人格设定窗口分三个标签页：

| 标签页 | 内容 | 可否编辑 |
|---|---|---|
| 人格参数 | 名字、自称、年龄、口头禅、人设事实、背景 | ✅ |
| 日记 | 开关、目录、天气城市 | ✅ |
| 固定人格 | system.md 九段摘要 + rules.md 全部红线 | ❌ 只读 |

### 分界线

| | 可编辑 | 只读 |
|---|---|---|
| 内容性质 | 数据（名字、列表、路径） | 行为描述（大段自然语言） |
| 表单能否表达 | 能 | 不能 |
| 改坏了会怎样 | 一眼看出来 | 人格崩坏，很难定位 |
| 例子 | 名字 = 大肥鱼 | 「七分软三分硬」 |

要精修只读部分：点「性格设定原文」按钮，用记事本直接编辑 `system.md`。

## 七、技术实现

### 文件

| 文件 | 作用 |
|---|---|
| `src/diary/index.ts` | 核心：判定 → 生成 JSON → 渲染 → 追加 |
| `src/diary/weather.ts` | 天气获取 + 英文转中文映射 |
| `src/config/index.ts` | `diary` 配置段（zod schema） |
| `src/index.ts` | 接入 `handleReply`，`void` 异步调用 |
| `src/server/http.ts` | `/api/diary/today`、`/api/diary/list` |
| `tests/diary.ts` | 78 项断言 |

### 关键设计

**1. 绝不阻塞对话**

```ts
if (cfg.diary.enabled) {
  void diary.maybeWrite(text, session.shortTerm.slice(-10)...);
}
```

用 `void` 而不是 `await`——写日记慢一点、失败都无所谓，回复必须准时。

**2. 绝不抛异常**

`maybeWrite` 整个包在 try/catch 里。LLM 挂了、天气接口挂了、磁盘满了、权限不足，
都只记一条 warn 日志，对话照常。

**3. JSON 解析容错**

LLM 输出可能带 ``` 包裹、前后有废话、字段缺失。`parseDiaryJson` 全部容忍：
- 抠第一个 `{` 到最后一个 `}` 
- 至少有一段正文（10 字以上）才算成功，避免写入空壳
- 缺的段落渲染时直接跳过，不留空标题

**4. 天气失败不阻断**

```ts
const weather = await this.weather.today(now).catch(() => '');
```

拿不到就空串，第一行少一段。

**5. 可注入时钟**

```ts
now: () => Date = () => new Date();
```

测试里替换成固定时间，才能验证「星期几算对 / 跨天换文件」。

## 九、已知限制

1. **每条要两次 LLM 调用**（判定 + 生成）。
   预筛能挡掉大部分噪音，但真正聊起心事时每条多花约 2-4 秒后台时间和约 1200 token。
   可以关掉 `enabled` 或调高 `minChars`。

2. **判定不是 100% 准**。
   偶尔会漏记（该记的没记）或多记（不该记的记了）。
   这是 LLM 判定的固有不确定性。

3. **天气依赖 wttr.in**。
   免费服务，偶尔慢或挂。拿不到就空着，不影响日记本体。
   如果长期不稳，可以换成和风天气之类的付费 API（改 `weather.ts` 一个文件）。

4. **地点是 LLM 猜的**。
   没有定位数据，只能从对话内容推测（「家中」「公司」「路上」）。
   猜错很正常。

5. **日记不可在 exe 里编辑**。
   可以直接用记事本改 `.md` 文件。
