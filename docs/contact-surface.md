# 接触面防护（Contact Surface）

> 回答一个关键问题：**机器人是普通 QQ 号，凭什么只跟你说话？**
> 日期：2026-10-19

---

## 1. 先把话说清楚：白名单不是平台限制

很多人（包括本文档上一版）会误以为「配了白名单，别人就联系不上机器人」。**这是错的。**

你配置里的 `pipeline.filter.allowedUsers` 只是程序内部的一行判断：

```typescript
if (!allowedUsers.includes(senderId)) return; // 就这一句
```

QQ 平台**不知道**这行代码存在。真实情况是：

| 你以为 | 实际发生的 |
|---|---|
| 别人加不上机器人 | **加得上**。QQ 不认识「白名单」这个概念 |
| 加了也发不了消息 | **发得了**。消息正常投递到协议端 |
| 机器人不会被拉进群 | **会被拉**。群邀请走的是 QQ 正常流程 |

白名单的作用只有一个：**在消息已经到达你机器之后，程序决定不回复它。** 它是「事后过滤」，不是「事前拦截」。

---

## 2. 那到底该怎么做：四层防护

单靠白名单是纸糊的。真正的防护是四层叠加，**每层独立生效**，任何一层失守还有下一层兜着。

```
          ┌─────────────────────────────────────────┐
 第 ① 层  │ QQ 账号隐私设置（手工配置，平台级）        │
          │ · 加好友必须验证                          │
          │ · 限制他人邀请入群                        │
          └─────────────────┬───────────────────────┘
                            ↓ 仍可能漏过来（验证消息、群邀请请求）
          ┌─────────────────▼───────────────────────┐
 第 ② 层  │ guard 自动处理（协议层，机器人主动拒绝）   │
          │ · 好友请求 → set_friend_add_request 拒绝  │
          │ · 群邀请   → set_group_leave 立即退群     │
          │ · 入群请求 → set_group_add_request 拒绝   │
          └─────────────────┬───────────────────────┘
                            ↓ 仍有漏网的（已是好友、已在群里）
          ┌─────────────────▼───────────────────────┐
 第 ③ 层  │ pipeline.filter（应用层，丢弃不回复）      │
          │ · allowedUsers 白名单                     │
          │ · dropGroupEvents 强制丢弃所有群消息       │
          │ · 未授权私聊不进上下文、不调 LLM           │
          └─────────────────┬───────────────────────┘
                            ↓
          ┌─────────────────▼───────────────────────┐
 第 ④ 层  │ 告警与观测（发现异常扩张）                 │
          │ · 非白名单私聊 → alert 日志               │
          │ · 被拉进群     → alert 日志 + /healthz    │
          └─────────────────────────────────────────┘
```

---

## 3. 第 ① 层：QQ 账号隐私设置（需要你手工做）

这是唯一一层**由平台执行**的防护，也是最重要的一层，因为它在消息到达你机器之前就起作用。

### 3.1 加好友验证

**路径**：手机 QQ → 设置 → 隐私 → 加我为好友时

| 选项 | 建议 | 说明 |
|---|---|---|
| 允许任何人加我为好友 | ❌ | 陌生人直接成为好友，第 ② 层只能拒绝"请求"而不是"已存在的友" |
| **需要验证信息** | ✅ **选这个** | 请求会落到 `request` 事件，robot 才能主动拒绝 |
| 需要正确回答问题 | ✅ 可选，更严 | 但你自己加的时候也得答对，记好答案 |
| 不允许任何人加我为好友 | 最严 | 你自己也加不上了，除非先用别的渠道 |

**为什么这个重要**：如果设成"允许任何人加"，别人直接成为好友，`request` 事件根本不触发，第 ② 层的好友请求拒绝逻辑就失效了。

### 3.2 群邀请限制

**路径**：手机 QQ → 设置 → 隐私 → 群聊相关（具体位置随版本变化）

目标：**尽可能限制"不被陌生人拉进群"**。QQ 各版本这叫法不同，找带有"允许被邀请入群""群聊隐私"字样的设置项。

如果找不到完全对应的开关，就依赖第 ② 层的自动退群兜底。

### 3.3 其他建议

- **不要把这个号挂到任何公开的地方**（群名片、论坛、贴吧）
- **不要用这个号扫码登录第三方网站**
- 开**设备锁**，防止异地登录
- 账号**不要和主号是同一个实名/常用设备**，降低关联风险

## 4. 第 ② 层：guard 自动处理（代码实现）

这一层是机器人的「反射神经」——它不等白名单判断，看到请求类事件就直接处理。

### 4.1 好友请求

```
收到 request 事件（sub_type=add）
  ├─ 发送者在 allowedUsers 里 → set_friend_add_request(approve=true)
  └─ 不在           → set_friend_add_request(approve=false)
```

**关键细节**：拒绝时**不要回复理由**。`rejectReason` 留空。

理由：带理由的拒绝是双刃剑——
- 好消息是对方知道"被拒绝"了，可能就不缠着了
- 坏消息是"该用户拒绝添加好友：xxx"这种提示很突兀，而且是**账号行为特征**

留空更接近"这个人就是没理我"的自然状态。反正对方也看不到机器人回复。

### 4.2 被拉进群

```
收到 notice 事件（notice_type=group_increase）且 user_id == 机器人自己
  └─ set_group_leave(group_id, is_dismiss=false)
```

**关键细节**：`leaveDelayMs: 0`，立刻退。

延迟退群=暴露风险。一个进群后 30 秒就退的号，和一个进群后待了 3 分钟才退的号比，后者更像是"人"——但也意味着更长的暴露窗口。私聊场景**优先选立刻退**，因为群里的每一秒都可能有消息进来。

**退群时不要发公告**（`announceOnLeave: false`）。悄悄退，不留话。

### 4.3 入群请求

有些群有"群主/管理确认"流程。这类请求一律 `set_group_add_request(approve=false)`。

### 4.4 未授权私聊

```
收到 message 事件（message_type=private）
  ├─ 发送者不在 allowedUsers → 直接 return，不进管线
  └─ 在 allowedUsers 里       → 正常处理
```

**关键要求：不进上下文、不调 LLM。**

只做「不回复」是不够的。如果消息进了短期上下文，会造成两个问题：
1. 下一次跟你说话时，prompt 里混进了别人的话
2. 每次调用都烧 token

所以拦截必须在管线**最前面**，在合并窗口之前。

## 5. 第 ③ 层：为什么还要应用层白名单

你可能会问：既然第 ② 层已经处理了请求，第 ③ 层是不是多余？

不多余。因为：

1. **第 ② 层只管「请求」，「已是好友」的情况管不了。** 万一是你之前误加了某人、或者在机器人上线前就已经是好友的人，`request` 事件根本不会触发。
2. **你有多个账号的情况**。你可能有主号、小号，第 ② 层的 autoAcceptWhitelisted 只认白名单里的号。
3. **代码会改。** 万一哪天有人加了新功能、改错了判断，第 ③ 层是最后一道保险。

**这才是「纵深防御」的含义**：不是相信某一层完美，而是假设每一层都可能出错。

---

## 6. 第 ④ 层：告警

如果 `guard.alert.enabled` 开启，以下事件会记 `alert` 级日志并在 `/healthz` 的 `status` 里体现：

| 事件 | 含义 |
|---|---|
| 非白名单私聊 | 有人绕过了一切加到了机器人，正在试探 |
| 被拉进群 | 机器人的能见度扩大了，可能被冒名或误拉 |
| 收到好友请求 | 有陌生人在尝试建立联系 |

**建议**：设个监控，看到 alert 日志就去看一眼。这三个信号单看都不严重，但**同时出现**说明有问题（比如有人批量扫描、或者这个号被挂到了什么地方）。

## 7. 直接回答你提的三个问题

### Q1：别人加机器人，机器人会回复吗？

**加了之后不会。** `guard.friendRequest.autoReject` + `pipeline.filter.allowedUsers` 双重拦截。

但注意时序：
- **加好友那一刻**：QQ 通知到协议端，机器人拒绝（靠第 ② 层）
- **如果第 ② 层失效**（比如隐私设成免验证、直接成好友）：第 ③ 层拦截消息，但不回复

所以答案是：**不会回复，但「不回复」这个动作本身，对方是能察觉的**。一个加了不说话的号，比直接拒绝更可疑。

### Q2：被拉进群，会发言吗？

**完全不会**，且会**立刻退群**。

`dropGroupEvents: true` + `scenario: private-only` 是代码层面的硬约束，即使你手滑改了 filter 配置，群消息也进不来。

### Q3：「所以其实可以做，只是会被封号」？

**技术上：对。** 你确实可以把白名单删掉，让它进群聊天、加好友、主动搭话。

**但「会被封号」这个表述是线性的，实际是梯度：**

| 行为 | 风险 | 为什么 |
|---|---|---|
| 私聊回陌生人 | 中 | 对方可举报；行为频率异常 |
| 待在群里不说话 | 低 | 没行为就没特征 |
| 群里被动回复 @ | 中高 | 响应速度、格式、内容都是特征 |
| 群里主动发言 | 高 | 多举报源 + 高频特征 |
| 主动加好友 / 群发 | 极高 | 典型营销号，容易被批量处置 |

**真正的封号触发链是**：行为异常 → 被人举报 → 人工复核 → 判定为自动化账号。

私聊场景里你只有一个人，**没有举报源**，所以风险确实低。但低不等于零：
- 新号 + 高频消息 = 可疑
- 秒回 + 格式工整 = 可疑
- 账号历史行为简单 + 突然活跃 = 可疑

所以本项目的策略一直是：**宁可少说，不要多说。** 回复慢一点、偶尔装死、不主动加人，这些「不完美」恰恰是伪装的一部分。

## 8. 老实说一个破绽

上面所有防护，有一个物理上无法解决的破绽：

> **机器人拒绝加好友 / 退群，这两个动作本身就会被对方看到。**

QQ 会提示「对方拒绝了你的好友请求」或者群里显示「xxx 已退出群聊」。

也就是说，**接触面防护做得越好，机器人这种存在就越容易被察觉到。**

这不是 bug，是这类方案的固有性质。缓解手段只有：

1. **尽量让自己别被注意到**（不起眼的小号、不挂任何公开信息）
2. **第 ① 层的隐私设置优先级最高**——在陌生人加到你之前就拦住，就不会有「拒绝」这个显式动作
3. **接受这个事实**——这个号本来就是小号，它的使命就是陪聊，不是社交
