# 启动器

一键启停四个组件的桌面程序。

## 生成 exe

双击 `build.bat`（用 Windows 自带的 .NET Framework 4 编译器，无需安装任何 SDK）。

生成两个文件：

| 文件 | 用途 |
|---|---|
| `鲸奈启动器.exe` | 图形界面版，双击使用 |
| `鲸奈状态.exe` | 命令行版，可查状态/启动/停止 |

## 图形界面

双击 `鲸奈启动器.exe`，会看到四个组件卡片：

- **机器人主程序** —— 端口 3000/8080
- **NapCat 协议端** —— 需要扫码登录
- **签名服务** —— Docker 容器
- **TTS 语音** —— 端口 9880

每个卡片右侧有「启动 / 停止」，底部有「一键全部启动」「全部停止」。
右侧还有一个「组件掉线自动拉起」开关（默认开启）。

状态每 3 秒自动刷新。组件以独立进程运行，**关掉启动器窗口不影响它们继续跑**。

## 自动拉起（看门狗）

长时间运行时，组件可能因为各种原因掉线（进程被系统回收、Docker 重启、
网络抖动导致崩溃等）。线上真的发生过机器人停了 2 天没人察觉的情况。

启动器每 30 秒检查一次四个组件，**连续 2 次（即 1 分钟）确认掉线才拉起**。
用「连续 2 次」是为了避免端口探测抖动造成重复启动。

自动拉起按依赖顺序进行：签名服务 → 协议端 → 机器人 → TTS。

不想让它自动重启时，把「组件掉线自动拉起」取消勾选即可。

## 命令行

```bat
鲸奈启动器.exe -status      查看四组件状态
鲸奈启动器.exe -startall    一键启动全部
鲸奈启动器.exe -stopall     全部停止
```

## 启动顺序

程序按依赖顺序拉起：**签名服务 → 协议端 → 机器人 → TTS**

机器人每次启动前会先 `npm run build`（约 3-5 秒），保证跑的是最新代码。

## 二维码显示

启动器会自动读取 NapCat 生成的二维码并显示在窗口下方，
放大到 600×600（最近邻插值，不模糊），用手机 QQ 直接扫。

登录成功后自动切换成「✅ 已登录，机器人已连上」。
NapCat 停止时不会显示过期二维码。

## 已知限制

- **NapCat 首次启动必须扫码**，会弹出 QQ 登录窗口
- NapCat 通过 hook QQ 进程工作，需要真实桌面会话（不能跑在无窗口的服务里）
- Docker Desktop 冷启动可能要 1-2 分钟，启动器最多等 120 秒

## 开机自启

想让它在 Windows 登录时自动启动全部组件：

```bat
autostart.bat on     开启自启
autostart.bat off    关闭自启
autostart.bat check  查看当前状态
```

开启后，登录时会以 `-silent` 模式运行：组件自动拉起，界面最小化在任务栏里
（双击可查看状态或停止），不打扰你。

关闭自启只是删除注册表项，不会影响已经在跑的组件。
