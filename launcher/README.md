# 启动器

一键启停四个组件的桌面程序。

## 生成 exe

双击 `build.bat`（用 Windows 自带的 .NET Framework 4 编译器，无需安装任何 SDK）。

生成两个文件：

| 文件 | 用途 |
|---|---|
| `大肥鱼.exe` | 图形界面版，双击使用 |
| `qinai-status.exe` | 命令行版，可查状态/启动/停止 |

## 图形界面

双击 `大肥鱼.exe`，会看到四个组件卡片：

- **机器人主程序** —— 端口 3000/8080
- **NapCat 协议端** —— 需要扫码登录（首次；之后自动快速登录）
- **签名服务** —— Docker 容器
- **TTS 语音** —— 端口 9880

每个卡片右侧有「启动 / 停止」，底部有「一键全部启动」「全部停止」。
右侧还有一个「组件掉线自动拉起」开关（默认开启）。

状态每 3 秒自动刷新。组件以独立进程运行，**关掉启动器窗口不影响它们继续跑**。

## 登录状态保持（重要）

**打开 exe 一般不需要重新扫码。** 这是靠三件事共同保证的：

1. **QQ 优雅退出** —— 关闭时走正常退出流程，让登录凭证落盘
2. **快速登录 `-q`** —— 启动 NapCat 时带上机器人 QQ 号，复用上次的登录态
3. **看门狗不碰 NapCat** —— 机器人掉线只重启机器人，绝不动 QQ

细节见 `../docs/login-persistence.md`。

NapCat 的 WebUI 端口 **6099** 是判断它是否活着的唯一可靠依据。
`TestLagrange()` 会优先查它，因为「有 QQ.exe 进程」并不能说明是 NapCat 拉起的那一个
（你自己开的 QQ 也叫 QQ.exe）。

## 自动拉起（看门狗）

长时间运行时，组件可能因为各种原因掉线（进程被系统回收、Docker 重启、
网络抖动导致崩溃等）。线上真的发生过机器人停了 2 天没人察觉的情况。

启动器每 30 秒检查一次四个组件，**连续 2 次（即 1 分钟）确认掉线才拉起**。
用「连续 2 次」是为了避免端口探测抖动造成重复启动。

自动拉起按依赖顺序进行：签名服务 → 协议端 → 机器人 → TTS。

**协议端有单独的豁免规则**：只要 6099 端口在听（NapCat 活着），
就不重启协议端，哪怕机器人连不上。因为重启协议端 = 杀 QQ = 掉登录。
这种情况重启机器人就够了，NapCat 的 WebSocket 客户端会自己重连。

不想让它自动重启时，把「组件掉线自动拉起」取消勾选即可。

## 命令行

```bat
大肥鱼.exe -status      查看四组件状态
大肥鱼.exe -startall    一键启动全部
大肥鱼.exe -stopall     全部停止
```

## 启动顺序

程序按依赖顺序拉起：**签名服务 → 协议端 → 机器人 → TTS**

机器人每次启动前会先 `npm run build`（约 3-5 秒），保证跑的是最新代码。

## 二维码显示

首次登录（或登录态失效）时，启动器会自动读取 NapCat 生成的二维码并显示在独立窗口里，
放大到 600×600（最近邻插值，不模糊），用手机 QQ 直接扫。

登录成功后窗口自动关闭。
NapCat 没在跑时不会显示过期二维码。

## 已知限制

- **NapCat 首次启动必须扫码**，会弹出 QQ 登录窗口
- NapCat 通过 hook QQ 进程工作，需要真实桌面会话（不能跑在无窗口的服务里）
- Docker Desktop 冷启动可能要 1-2 分钟，启动器最多等 120 秒
- 启动器需要管理员权限（NapCat 注入 QQ 需要），所以会弹 UAC

## 开机自启

想让它在 Windows 登录时自动启动全部组件：

```bat
autostart.bat on     开启自启
autostart.bat off    关闭自启
autostart.bat check  查看当前状态
```

开启后会注册一个**计划任务**（不是注册表 Run 项），
以最高权限静默启动，不弹 UAC。以 `-silent` 模式运行：
组件自动拉起，界面最小化在任务栏里（双击可查看状态或停止）。

关闭自启只删除计划任务，不会影响已经在跑的组件。

## 构建注意事项

`build-and-sign.ps1` 里有两个容易踩的坑，已经修好并加了注释：

1. **必须存成 UTF-8 with BOM**
   PowerShell 5.1 读无 BOM 的 UTF-8 时会按 GBK 解释，
   脚本里的中文文件名（`大肥鱼.ico`）会变成乱码，csc 报 `CS2021: 文件名太长或无效`。

2. **部署目标要排除 `_trash*.exe`**
   启动器运行中被重新编译时，旧 exe 删不掉会被改名成 `_trash.exe`。
   如果部署逻辑只看「第一个 exe」，就会把新版本写到 `_trash.exe` 上，
   真正的大肥鱼.exe 还是旧的。现在按「含中文字符 + 排除 _trash/status」筛选。
