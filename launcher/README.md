# 启动器

一键启停四个组件、管理人格与日记、执行所有维护操作的桌面程序。

**所有操作都在这个 exe 里。** 不需要命令行，不需要双击 .bat。

---

## 生成 exe

在启动器里点 **工具箱 → 重建启动器 exe**，或直接跑 `build-and-sign.ps1`。

生成两个文件：

| 文件 | 用途 |
|---|---|
| `大肥鱼.exe` | 图形界面版，双击使用 |
| `qinai-status.exe` | 命令行版，可查状态（`-status` / `-startall` / `-stopall`） |

---

## 主界面

### 四个组件卡片

| 组件 | 说明 |
|---|---|
| **机器人主程序** | 端口 3000/8080 |
| **NapCat 协议端** | 需要扫码登录（首次；之后自动快速登录） |
| **签名服务** | Docker 容器 `ntqq-sign-server` |
| **TTS 语音** | 端口 9880 |

每个卡片右侧有「启动 / 停止」。

### 六个操作按钮

| 按钮 | 作用 |
|---|---|
| **一键全部启动** | 按依赖顺序拉起四个组件（等到真就绪，不是固定 sleep） |
| **全部停止** | 全部关掉 |
| **查看日志** | 内置日志查看器（见下） |
| **编辑人格设定** | 人格参数 / 日记 / 只读设定三个标签页 |
| **工具箱** | 所有维护操作（见下） |
| **组件掉线自动拉起** | 看门狗开关（默认开） |

状态每 3 秒自动刷新。组件以独立进程运行，**关掉启动器窗口不影响它们继续跑**。

## 工具箱

以前这些操作散落在 `.bat` / `.ps1` 里，现在全部收进 exe。

### 开机自启

一个复选框。勾上 = 注册计划任务 `QinaiChatmateLauncher`，
Windows 登录时以最高权限静默启动（不弹 UAC）。

用的是 `schtasks`，不是注册表 Run 项 —— 后者会每次登录弹 UAC。

### 数据与日志

| 按钮 | 打开 |
|---|---|
| 查看日志 | 内置查看器（见下节） |
| 打开数据目录 | `qq-netizen/data` |
| 打开日记目录 | 从配置里读，默认 `D:\日记` |
| 打开 NapCat 日志 | `napcat/napcat/logs` |

### 维护

| 按钮 | 作用 | 有确认? |
|---|---|---|
| 导入收藏表情包 | 跑 `tools/import-stickers.ts`，从 QQ 收藏拉表情 | ✅ |
| 清理重建残留 | 删 `_trash*.exe`（被占用的会跳过，重启后可清） | ❌ |
| 重建启动器 exe | 跑 `build-and-sign.ps1` | ✅ |
| 重置会话状态 | 清情绪/亲密度（目前只提示，需先停机器人） | ✅ |
| 备份配置 | 复制 `config/` 到 `backups/时间戳/` | ❌ |
| 打开程序目录 | 资源管理器 | ❌ |

## 内置日志查看器

**工具箱 → 查看日志**，或主界面 **查看日志**。

| 区域 | 内容 |
|---|---|
| 左侧 | 日志文件列表（按修改时间倒序） |
| 右侧 | 文件内容（只读，等宽字体，可横向滚动） |
| 顶部 | 「自动刷新（2 秒）」勾选框 + 重载 + 打开文件夹按钮 |

以前是「打开日志目录」→ 资源管理器 → 找文件 → 记事本 → 拖到底。
现在点一下就能看，还能自动刷新盯着。

只读文件尾部 200KB，避免大文件卡死。

## 人格设定

三个标签页：

| 标签页 | 内容 | 可编辑 |
|---|---|---|
| 人格参数 | 名字、自称、年龄、口头禅、人设事实、背景 | ✅ |
| 日记 | 开关、目录、天气城市 | ✅ |
| 固定人格 | system.md 九段摘要 + rules.md 红线 | ❌ 只读 |

保存后写到 `config/personas/default.yaml` 和 `config/local.yaml`（日记配置）。
需要重启机器人生效。

## 登录状态保持（重要）

**打开 exe 一般不需要重新扫码。** 靠三件事：

1. **QQ 优雅退出** —— 关闭时走正常退出流程，让登录凭证落盘
2. **快速登录 `-q`** —— 启动 NapCat 时带上机器人 QQ 号，复用上次登录态
3. **看门狗不碰 NapCat** —— 机器人掉线只重启机器人，绝不动 QQ

细节见 [login-persistence.md](../qq-netizen/docs/login-persistence.md)。

NapCat 的 WebUI 端口 **6099** 是判断它是否活着的唯一可靠依据。
`TestLagrange()` 优先查它，因为「有 QQ.exe 进程」并不能说明是 NapCat 拉起的那一个
（你自己开的 QQ 也叫 QQ.exe）。

---

## 自动拉起（看门狗）

每 30 秒检查一次四个组件，**连续 2 次（1 分钟）确认掉线才拉起**。
避免端口探测抖动造成重复启动。

自动拉起按依赖顺序：签名服务 → 协议端 → 机器人 → TTS。

**协议端有豁免规则**：只要 6099 端口在听（NapCat 活着），就不重启协议端，
哪怕机器人连不上。因为重启协议端 = 杀 QQ = 掉登录。
这种情况重启机器人就够了，NapCat 的 WebSocket 客户端会自己重连。

---

## 启动顺序

**签名服务 → 协议端 → 机器人 → TTS**

机器人每次启动前会先 `npm run build`（约 3-5 秒），保证跑的是最新代码。

## 二维码显示

首次登录（或登录态失效）时，自动读取 NapCat 生成的二维码显示在独立窗口，
放大到 600×600（最近邻插值，不模糊），用手机 QQ 直接扫。

登录成功后窗口自动关闭。NapCat 没在跑时不会显示过期二维码。

## 已知限制

- **NapCat 首次启动必须扫码**，会弹出 QQ 登录窗口
- NapCat 通过 hook QQ 进程工作，需要真实桌面会话（不能跑在无窗口的服务里）
- Docker Desktop 冷启动可能要 1-2 分钟，启动器最多等 120 秒
- 启动器需要管理员权限（NapCat 注入 QQ 需要），所以会弹 UAC
- `_trash*.exe` 被 Windows 锁住时删不掉，重启后可清（工具箱里有对应按钮）

## 构建注意事项

`build-and-sign.ps1` 里有两个容易踩的坑，已修好并加了注释：

1. **必须存成 UTF-8 with BOM**
   PowerShell 5.1 读无 BOM 的 UTF-8 时按 GBK 解释，
   脚本里的中文文件名（`大肥鱼.ico`）变乱码，csc 报 `CS2021: 文件名太长或无效`。

2. **部署目标要排除 `_trash*.exe`**
   启动器运行中被重新编译时，旧 exe 删不掉会被改名成 `_trash.exe`。
   如果部署逻辑只看「第一个 exe」，新版本会写到 `_trash.exe` 上，
   真正的大肥鱼.exe 还是旧的。现在按「含中文 + 排除 _trash/status」筛选。
